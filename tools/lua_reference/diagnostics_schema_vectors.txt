# canonical serializer and fnv1a64 content digest.
#
# Generated from the real Lua implementation (`love .` against a scratch copy
# of core/, sim/, data/, and game/online/diagnostics_schema.lua). This vector
# is frozen and cannot be regenerated: the Lua implementation it was
# captured from no longer exists in this repository. A failing differential
# against it is a finding about the Rust or TypeScript code under test, not
# a fixture to refresh. See tools/lua_reference/README.md for provenance.
# Asserted from:
#   - Rust: crates/gc-netcode/src/diagnostics_schema.rs (tests::shared_vectors_agree_with_lua),
#     which reads this file directly.
#   - TypeScript: the equivalent guarantee for @gc/online's diagnostics_schema.ts
#     is covered separately by diagnostics_schema_crosslang.spec.ts, which carries
#     its own separately-captured cases rather than reading this file.
#
# Every case validates against one shared shape, defined identically in each
# language's test (a "test_record" with an `identity` section — id/integer/
# boolean/enum/hash/optional-text fields — and a `canonical` section — a
# `map<id>` field, an `array<integer>` field, and an optional `number`
# field). The exact shape is reproduced in each test file; see there for the
# field-by-field definition.
#
# Format: one vector per non-comment, non-blank line, tab-separated:
#   label<TAB>encoded_hex<TAB>digest
# `encoded_hex` is the lowercase hex encoding of diagnostics_schema.encode()'s
# raw byte output (kept as hex, not raw bytes, so this file stays plain ASCII
# even though the "non_utf8_byte_in_text_field" case's payload deliberately
# contains a byte that is not valid UTF-8). `digest` is the expected lowercase
# fnv1a64 hex digest of those same raw bytes (diagnostics_schema.digest()'s
# output).
#
# Cases:
#   ordinary_record                  - a normal, fully-populated record.
#   empty_values                     - an omitted optional field, an empty
#                                       map, and an empty array.
#   non_utf8_byte_in_text_field      - a `text` field whose value contains a
#                                       raw 0xff byte (invalid UTF-8) and an
#                                       embedded 0x00 byte.
#   negative_and_fractional_numbers  - negative integers, a value at
#                                       -MAX_SAFE_INTEGER, and a non-integer
#                                       `number` field (exercises `%.17g`
#                                       formatting, not just `%d`).
#
# Two more lines, generated the same way, pin `diagnostics_schema.tuple_digest`
# (used by desync_package's wire-set digest) independent of any record shape:
#   tuple_digest_two_parts  - tuple_digest("desync_input_wires", {"GCIP;1;G;wire-one", "GCIP;1;H;wire-two"})
#   tuple_digest_empty      - tuple_digest("desync_input_wires", {})
# For these two, `encoded_hex` is empty (tuple_digest has no separate encode
# step to capture) and only `digest` is meaningful.
